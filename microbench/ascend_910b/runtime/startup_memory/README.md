# Source-bound native startup memory

This runner observes one real vLLM-Ascend startup without requests. The default invocation prints a plan and does not import Torch/vLLM, read model assets or create output. Device execution requires the explicit execution flag, a fresh output path under the assigned remote task directory, and the hardware owner's current idle-device check. The runner preserves BF16 TP1, utilization 0.8, max model length 8192, max batched tokens 8192, max sequences 256, chunked prefill, prefix caching and seed 42; it does not pass `--block-size` or force eager mode.

`bindings.json` is the unique versioned AST binding owner for the reviewed installed vLLM `0.18.0+empty` and Ascend `0.18.0` source. Its AST representation is generated with the installed Python 3.11; a different Python minor or executable source fails before module execution. To regenerate, use `prepare_bindings.py --source-snapshot <captured-source-directory>` with that Python minor. Third-party source bytes belong in the registered `profiler_output` campaign, rather than this directory. The bound dependencies include the upstream GPU capture delegate, native reset alias, memory profiler and block-size resolver, not only the outer worker hooks.

The observer never adds reset, synchronization, cache eviction, tensor allocation or model operations. It wraps the two existing NPU/accelerator reset aliases with the same callable and records before/after reads and a process-local reset epoch. Epoch zero explicitly means the preceding reset is unknown. In the reviewed source, model loading's `DeviceMemoryProfiler` invokes `NPUPlatform.get_current_memory_usage` at entry and exit; each original call resets native peak stats. `memory_profiling` performs another original reset before profiling. Capture delegates to `GPUModelRunner.capture_model`; the worker performs ATB warmup after capture. Completion therefore requires the full worker warmup return and all bindings/phases from the same process.

Records preserve native allocated/reserved current and peak, free/total integer bytes, original integer snapshots, original floating budgets with hexadecimal representations, and the allocator's returned integer budget. They also record resolved cache blocks, actual KV group block/page sizes, tensor byte extents, block counts and kernel block sizes. The reviewed `refresh_block_size` changes an unspecified block size to 128 and forces a non-128 size to 128 when prefix caching or chunked prefill is enabled for a non-hybrid model. This native configuration must not be labelled equivalent to a simulator's block size 16.

An authorized hardware owner stages this directory intact, including `bootstrap/` and `bindings.json`, and runs the following command inside `<ascend-container>` after confirming the device and port are still free. Device 1 is only a candidate until that check.

```bash
python3 -B <repository-root>/wt-normal-startup-20261026/startup_memory/startup_memory_runner.py --model <model-path> --raw-output <repository-root>/wt-normal-startup-20261026/profiler_output/serving/ascend_910b/startup_native_memory_20261026/run03 --device-index 1 --port 19080 --startup-timeout-seconds 300 --execute-authorized-device-startup
```

The controller stops its own process group after collection or timeout. Runtime cache/log output stays below the raw output directory. `TMPDIR` uses the repository’s single-task `/tmp` exception: a newly created, unique `/tmp/<validated-task-name>-<random-id>` directory (for the example, `/tmp/wt-normal-startup-20261026-<id>`). The runner records its exact path in `capture_identity.json` before startup and removes only that directory after stopping the startup, including failure and timeout paths; existing directories are never reused or deleted. It does not use `/tmp` itself as a shared workspace, retain temporary files across tasks, or use home directories. This avoids both long ZMQ Unix socket paths and NFS-backed temporary shared-library cleanup. The installed compiler synchronously compiles then loads a callback shared library inside `TemporaryDirectory`; NFS plus that loaded-library lifetime supports this local-filesystem workaround, but no `.nfs` artifact was preserved, so the precise run02 cleanup cause remains unproven. A successful collection is candidate evidence only: it does not set normal capacity or provider acceptance, establish equality with historical software/configuration, or publish a runtime policy. Pull back raw source bindings, counters and logs and clean only the task's own remote files according to the repository lifecycle rules.
