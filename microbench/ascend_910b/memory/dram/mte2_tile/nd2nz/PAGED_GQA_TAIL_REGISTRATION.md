# 910B paged-GQA short tail-page ND2NZ descriptor registration

- Owner/baseline: worktree `wt-910b-decode-host-device`, baseline `5abb4cb21`. Runner profile `paged_gqa_tail` in `aic_mte2_nd2nz_stride_runner.py`.
- Why this cell exists: `src/kernel/predictors/flash_attn.py:1394-1417` derives the paged K/V row stride exactly (`physical_kv_row_stride = num_kv_heads * head_dim = 1024` for D128/HKV8) but withholds it unless `measured_paged_kv_stride` holds. Both of that predicate's clauses are structurally unreachable in decode: clause 1 requires `kv_layout == "paged"` while serving runs `paged_varlen`, and clause 2 requires every `actual_s2 % 128 == 0` while a decode step appends one token, so each request's last block-table page carries `(context + 1) mod 128` rows. Measured on production decode shapes (qwen3-4b, `fia_paged_stride_gate.py`), the observed tails are 61 rows at 700 computed tokens and 1 row at 1024/2048. The existing `paged_gqa_128` cells measure full 128-row pages only, so the short final page of every decode panel has no measured service.
- Source scope: the same CANN 8.5.1 D128/HKV8 paged K/V ND2NZ descriptor already covered by `paged_gqa_128`, at a shorter row count. No new descriptor class, no new operator, no page-table term.
- Cells (frozen before any data is opened): `(rows, columns, source_row_stride_elements)` = `(61,128,1024)`, `(81,128,1024)`, `(127,128,1024)`, plus frozen validation peers `(61,128,128)` and `(61,128,4096)`. Active AIC groups `(22, 23, 24)`. The row set is the widest tail plus the interior widths production shows; it is defined by the `(context + 1) mod 128` arithmetic, never by an observed duration, MAPE or residual. The 22/23 group counts are included because `_strided_active_aic_group_is_measured` is already False at several production decode grids, which is a second sub-gap inside clause 2.
- **Amendment, 2026-09-27, made before any tail duration was opened.** The originally registered `(1,128,1024)` cell is withdrawn. On deployment the instrument refused it with its own hard validation error, `AIC strided MTE2 differential interval did not increase`, and produced no row of output: a 1-row descriptor is 256 source bytes, which the short/long differential method cannot resolve. This is a domain limit of the instrument, established by a validation refusal rather than by inspecting any duration; no measured value influenced the amendment. A control run of the existing frozen `paged_gqa_128` profile on the same deployment passed on every cell (`validation=pass`, 8/16/24 active AIC groups), which is what establishes that the refusal is specific to the 1-row geometry and not to the deployment, binary or container. Consequence to carry forward: decode tails below the resolvable bound are **unsupported by this instrument** and must be reported as such rather than interpolated or extrapolated from the measured widths — note that a 2048-token context yields exactly a 1-row tail, so this unsupported region is reached in production.
- Hypothesis: the short tail page's per-descriptor ND2NZ service is described by the same strided mechanism as the full page, at its own measured row count. The probe neither assumes that the tail is cheaper or dearer per row than the full page, nor supplies any correction factor.
- Acceptance (all required; written before data exists): the runner's own validation must pass for every cell; stderr must be empty; per cell, across fresh processes, `(max(medians) - min(medians)) / median(medians) <= 5%`. The two frozen peers at stride 128 and 4096 must bracket the stride-1024 value at the same row count, in the same order the `paged_gqa_128` peers do. Failure of any criterion rejects the whole campaign with no resampling, no production change, no HWSpec change and no Forward evaluation.
- Publication boundary: a passing capture is evidence for this descriptor's service at these row counts only. It does **not** by itself license publishing the paged stride in Forward. Making it load-bearing additionally requires relaxing `measured_paged_kv_stride` clause 2 to admit a short final page — a source-semantics change that must be argued from the CANN source, not from this measurement — and it still leaves two independent fail-open holes: `formula.py:3832` (`_gqa_group_fits_finite_stream`, ≤160 drained D128 descriptors per worker, measured to fail from about B=32 at 2 000-token contexts) and `flash_attn.py:1946` (`_has_graph_padding`, which removes the per-AIC program on every padded decode step). Those three must be closed together, or in an order where each step is separately verifiable against the measured per-step device windows; closing one alone has already been falsified twice in this area.
