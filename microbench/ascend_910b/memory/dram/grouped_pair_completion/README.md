# Grouped pair completion probe

This standalone CANN 8.5.1 probe measures the completion span of a finite BF16 GroupedMatmul GM-to-L1 operand-pair stream. The default campaign measures the source-selected M16/N256/K64 tile. Tail campaigns allocate the source-selected M64 or M128 A buffer while copying and loading an active M16, M32, or M48 tail, matching `SetSingleShape(curSingleM, ...)` without reproducing a production operator. Each AIC repeatedly reads its resident A tile and a disjoint cold B tile, preserves the two-buffer A/B issue order, and every four pairs establishes an MTE2-to-MTE1 dependency followed by the source-shaped A/B L1-to-L0 loads. A separate 512 MiB B stream is completed immediately before the timed launch to evict the timed weights. It executes no Cube arithmetic, output traffic, routing, activation, reduction, or complete production operator.

Configure and build inside the agreed 910B container with `ASCEND_HOME_PATH=/usr/local/Ascend/cann-8.5.1 cmake -S . -B build -DSOC_VERSION=Ascend910B2`, then `cmake --build build -j 8`. Run `grouped_pair_completion_runner.py` with an idle physical device; the default long-stream campaign captures M16 at 256, 1024, 4096, and 8192 pairs per worker in rotated order, one fresh process per cell. The `m64_tail16`, `m64_tail32`, `m128_tail16`, `m128_tail32`, and `m128_tail48` campaigns use matching `-DGROUPED_PAIR_BASE_M=<64|128> -DGROUPED_PAIR_ACTIVE_M=<16|32|48>` builds and capture 512, 1024, 3072, and 6144 pairs per worker. Their `_k2880_stride` counterparts additionally use `-DGROUPED_PAIR_B_ROW_STRIDE=2880` and a bounded 512-tile-per-worker source ring whose 384 MiB aggregate copied footprint exceeds the shared 192 MiB L2. The `_k2880_tile` campaigns bracket the 45-step K2880 `IterateAll` boundary with 32, 44, 48, and 64 pairs rather than concatenating multiple output tiles into one steady stream; validate them with `grouped_k2880_output_tile_completion_report.py`. The `m128_extension` campaign is built with `-DGROUPED_PAIR_BASE_M=128` and captures 8192, 12288, 16384, and 24576 pairs per worker. The previously published 16--128-pair short-stream campaign remains recorded by its versioned reference.
