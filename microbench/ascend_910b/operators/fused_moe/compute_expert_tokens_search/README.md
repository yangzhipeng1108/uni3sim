# MoeComputeExpertTokens key-1003 target-step probe

This standalone CANN 8.5.1 probe isolates one source-shaped key-1003 target step on one AIV: a binary search over a UB-resident `LocalTensor<int32_t>`, the ordered `V_S` wait, one-element `Duplicate`, and the following `V_S` set. GM setup, task launch, `SyncAll`, workspace traffic, reduction, and the rest of the production operator remain outside the device-side timed interval. It does not execute a production operator or consume production/evaluation duration.

Configure and build inside the agreed 910B container with `ASCEND_HOME_PATH=/usr/local/Ascend/cann-8.5.1 cmake -S . -B build -DSOC_VERSION=Ascend910B2`, then `cmake --build build -j 8`. Run with `ASCEND_RT_VISIBLE_DEVICES=<physical-device> ASCEND_DEVICE_ID=0 ./build/compute_expert_tokens_search --batch input_elements target iterations [...]`; the host program requires logical device zero after physical-device remapping and prints one validated CSV row per frozen cell.

The published campaign uses input lengths `1,2,4,8,16,32,64,128,256,320`, lower and upper miss targets, plus three in-range 320-element targets, with 65,536 chained iterations per cell. Runs 1 and 2 determine one affine service in search comparisons; run 3 is the independent holdout. The reference records the fixed sweep, raw hashes, cross-run stability, fit error, source identity, and composition boundary. Production Forward obtains target counts and exact search depths analytically from the parent FusedMoE routing histogram; the public-source-to-installed-binary binding remains an explicit limitation.
