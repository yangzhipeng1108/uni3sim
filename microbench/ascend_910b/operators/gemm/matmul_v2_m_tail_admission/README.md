# MatMulV2 M-tail admission

This independent CANN 8.5.1 mechanism microbenchmark isolates the asynchronous client admission difference between a 16-element-aligned M extent and an otherwise identical partial-M extent. It does not invoke the production MatMulV2 kernel or measure a complete GEMM duration.

Twenty-two AIC workers each execute two `IterateAll<false>` calls with BF16 GM/ND operands, base tile `(48,96,64)`, two A1/B1 buffers, and either four or eight base-K tiles per L1 descriptor. Results are indexed by all 24 physical AIC identifiers because a 22-block launch need not occupy a contiguous physical prefix; exactly 22 populated rows are required. The dynamic-tail control crosses logical M `{40,48}` while holding every tiling field, K extent, worker count, source order, and allocation fixed. The static no-tail control uses the same M48 program but disables `enableSetTail` and supplies the physical base/single-core extents through `MatmulConfig`, matching the source specialization exposed by CANN's `NoTailM/NoTailN/NoTailK` predicates. K is swept over `{512,1024,2048,4096}` so a result can identify a per-K-control recurrence instead of becoming a production-shape lookup; only K4096 matches the validated production boundary, while the shorter values remain independent controls.

The per-tile timestamps end immediately after each asynchronous `IterateAll<false>` call returns and describe source admission/back-pressure. A separate program timestamp ends after the final `PIPE_ALL` drain and isolates the complete worker-local two-tile source program, including the server-side iterator/control branch. This synthetic mechanism span is not a production operator duration and cannot be used as a shape residual correction.
