# MatMulV2 small-M lifecycle

This independent CANN 8.5.1 mechanism probe distinguishes the finite worker-local MatmulImpl lifecycle from the MTE2-only source program for the two small-M source geometries used by the key-98513 family. It does not invoke a production operator or measure a production GEMM shape.

The sweep uses base tile M16, base K64, two N tiles per worker, two A1/B1 buffers, eight base-K tiles per L1 descriptor, N in `{96,112}`, and K in `{1024,2048}`. The static control uses an aligned M16 no-tail specialization; the dynamic control uses logical M1 with the same physical tiling. N96 launches 22 AIC workers and N112 launches 23, matching the source-defined worker populations while the short K sweep remains independent of the evaluated K11008/K13824/K14336 workloads. Program timestamps end after `PIPE_ALL`; only cross-K Scalar-pipe lifecycle slopes and the matched dynamic-minus-static delta are eligible mechanism outputs. Complete program durations and MTE2 durations are diagnostic only and cannot enter Forward.

Build inside the agreed 910B container with `source /usr/local/Ascend/cann-8.5.1/set_env.sh`, `cmake -S . -B build -DASCEND_HOME_PATH=/usr/local/Ascend/cann-8.5.1 -DSOC_VERSION=Ascend910B2`, and `cmake --build build -j8`. Run on one explicitly remapped idle device with `ASCEND_RT_VISIBLE_DEVICES=<physical-device> ASCEND_DEVICE_ID=0 ./build/matmul_v2_small_m_lifecycle --base-n <96|112> --m <1|16> --k <1024|2048> --static-no-tail <0|1>`; static mode requires M16 and dynamic mode requires M1. Capture `PipeUtilization` for both K values because the measured output is the per-output/base-K Scalar service, not the complete program span.
