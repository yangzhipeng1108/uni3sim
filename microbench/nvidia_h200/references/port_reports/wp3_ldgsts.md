# WP3 LDGSTS / staged-operand / finite-stream: H200 re-measurement report

Worker branch `h200-port-wp3_ldgsts` (baseline `8e7ae7db1`). Every A800-derived parameter in scope was re-measured on H200 GPU 2 (`ssh the capture host`) with an owner copy of the A800 probe that differs only in hardware coupling (listed in each source header), a scripted runner and a scripted derivation. Probes and runners were committed first (`aeb34ee30`, depth-3 first-event fix `55de4e061`); every capture records the commit it ran. Per-clock values use the measured 1.98-GHz H200 SM clock. No production or evaluation duration is consumed anywhere.

## Notes and caveats

1. Residency by construction. The 228-KiB H200 SM admits more CTAs than the A800 164-KiB SM for three resource classes. The owner copies pad only the dynamic shared reservation (never touched by the ring) so that the occupancy query reports exactly the A800 residency, and every probe still fails closed otherwise: K32 depth-6 74,752 -> 77,824 B (2 CTAs/SM instead of 3); 64x64 depth-6, finite stream and 3-slot mixed stream +20 KiB (1 CTA/SM instead of 2). The other classes (82,944 B, 76 KiB, 147,456 B, 81 KiB, 5-slot mixed) already keep the A800 residency on H200.
2. `ldgsts_initial_32b_*`: the A800 values are event-timed payload GB/s x 2 / 32 B / 1.14 GHz, where the factor 2 (Xbar LDGSTS counter bytes = 2 x payload) came from A800 NCU. Nsight Compute is not installed on the H200 host, so the factor is carried, not re-verified (the H200 binary issues the same `LDGSTS.E.BYPASS.128` for the same PTX). The probe prints per-SM GB/s with one decimal, so the grid-1 and grid-2..32 rates both quantise to 31.5 GB/s -> 0.99432 txn/cycle; this is the probe's own output precision, as on A800.
3. `ldgsts_finite_resident_*`: A800 used NCU `gpu__time_duration` x NCU clock. H200 uses the Nsight Systems `cuda_gpu_trace` kernel duration (same GPU per-kernel timeline) x the clock-gated 1.98 GHz. The NCU dynamic counter-closure gate is recorded `null`; the static gates (32 `LDGSTS.E.BYPASS.128`, no spill) pass; the sm_90 build uses 80 registers (A800 sm_80: 79). The same NCU substitution applies to rows #9/#10, whose counter closure is replaced by the probes' own analytic per-block repeat counts (checked every sample).
4. Mixed-tier startup: at one wave the H200 residual is 394 ns (A800 5120 ns). Same-cell residuals (50% L2, 3 slots) are -1964 / -1038 / 394 / 1538 / 1076 ns at grids 64 / 96 / 132 / 264 / 371, the 5-slot ring gives -440 / -1016 ns at 132 / 264, and pure-DRAM cells stay negative, so on H200 the finite mixed-tier fill is bounded and small, within the ~1-2 us noise of the event-timed short launches. The value is reported as measured by the A800 rule; the integrator may treat it as not significantly different from zero.
5. Depth-3 curve: with the verbatim A800 host loop, the first event-timed launch of each H200 process read ~2 us slow and failed the A800 zero-round stability gate (relative > 15% and absolute > 2.1 us) in 4 of 5 attempts (`wp3_depth3_r1_t1..t3`, `wp3_depth3_r2_t1`; `r2_t2` passed). Commit `55de4e061` adds one discarded event-timed zero-round launch before the measured matrix; both published captures (`wp3_depth3_r1f_t1`, `wp3_depth3_r2f_t1`) use it. The A800 `source_order.validation` against 35 x the configured L2 first-request latency is not re-established: there is no H200-measured L2 first-request latency; the measured H200 launch-subtracted L2 finite residual medians are 23628 and 21349 ns.
6. Finite stream: the A800 reference was derived by hand from one capture; the H200 derivation is scripted (`publish` in the runner) and uses the smaller of two capture medians per cell so the floor never exceeds a measurement (verification block in the reference).
