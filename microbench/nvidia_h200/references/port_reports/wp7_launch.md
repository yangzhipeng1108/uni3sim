# WP7 launch / runtime / task-floor H200 re-measurement

Branch `h200-port-wp7_launch`, baseline `8e7ae7db1`, GPU 0 of `the capture host` (NVIDIA H200, driver 575.57.08, UUID `capture-device-3628c660fa6e`). Probes built locally with CUDA 12.2 `nvcc -arch=sm_90 -cudart static`; nsys 2025.6.1 on the host; torch 2.11.0+cu129 (vLLM 0.24 env) for the torch probe. The SM clock is not lockable: every timed capture ran with `nvidia-smi -i 0 --query-gpu=clocks.sm,utilization.gpu -lms 50`, and a capture with no busy sample or any busy sample below 1980 MHz was rejected (counts below). ## Notes for integration

- **M (grid 108 above 132).** The capture added grid 108 (the A800 full-chip width) as an extra point. On H200 it costs 94.5-101.9 ns over a single CTA in every trial and block size, more than the full-chip grid 132 (≈69 ns). Because 108 is not an A800 grid it is not tabled; including it would carry 99.3 ns through the running maximum into the 132 entry. Values are in the reference's `provenance.untabled_grid_108_*`. Also the A800 probe's `scratch[0]` write is out of bounds at the nominal smem = 0 point; sm_90 faults on it (first run `cta_dispatch_wp7_failed_smem0`), so the owner copy allocates `smem + 4` bytes (header comment); two-wave grid 264 is block-dependent (152-564 ns) as on A800.
- **I (gates fail).** H200 small-grid kernel durations are bimodal with a period-4 launch pattern (e.g. grid 3 x 512: 864-1024 ns and 1056-1185 ns alternating; the same period-4 pattern is visible in the span-floor raw). The A800 lower-envelope rule subtracts the largest training excess over the per-cell minimum (272.4 ns) from the intercept, so the floor sits ≈24 % below the cell medians and the A800 median-accuracy gates (5 % / 15 %) fail; the unconstrained fit is base 1015.47 ns with the same slopes. The published parameters are the A800-rule lower envelope; whether the H200 config should adopt them despite the failed gates is an integration decision.
- **L.** The H200 torch 2.11 template is `vectorized_elementwise_kernel<8, BinaryFunctor<BFloat16…>>` with 128 threads and grid ceil(elements/1024) (A800 torch 2.8: vec 4, same grid rule), read from an nsys trace (`profiler_output/microbench/nvidia_h200/bf16_launch_geometry_wp7_20260925/`). The curve is not monotone at one point (16384: 1475.1 < 8192: 1481.5 ns); no running maximum is applied (the A800 rule has none). The largest step (2.79x) is between 4194304 and 8388608 elements, one sample below the nominal 60 MiB L2 crossing (recorded `l2_capacity_transition.elements` = 16777216). Cross-sample spread 15.9 % (A800 5.4 %).
- **D.** The A800 probe has no runner/report and its grid list, spin lengths and sample counts are unrecorded; grids {8,16,32,48,64}, spins {4096, 32768} cycles, 50 launches x 2 rotations and the median-per-cell / max-over-cells rule are this worker's scripted reading of the yaml comment and probe header (stated in the reference). Per-cell medians are 928-1120 ns for both FA2 geometries.
- **B vs K.** B (nsys duration) and K (CUDA-event batch/64) use different timers; K's graph-node minimum is 0.92-1.30 x B's floor at shared grids.
- **J software_revision** is kept as the torch 2.8.0 source-semantics label with `sm90` (`pytorch_2.8.0_cuda_12.8_sm90_source_semantics`); the TensorIterator offset-calculator semantics were not re-audited against torch 2.11.
