## Development-only profiles

The adapter also registers explicitly non-production profiles for `nvidia_a800`, `metax_c500`, and `ascend_910b`, separately content-addressed for AllReduce and AllGather. They exist to unblock analytical Serving integration and every result that consumes them is marked `projected_with_protobridge_development_only`, which is unsupported for accuracy, publication, hardware-comparison, or DSE claims.

- User-confirmed inputs on 2026-08-26 and 2026-08-27: A800 eight 25 GB/s unidirectional NVLink lanes and non-blocking switched topology; C500 three 64 GB/s unidirectional MetaXLink peer links and full-mesh topology; 910B seven 28 GB/s unidirectional HCCS peer links and full-mesh topology; collective startup values 55/100 us, 5/10 us, and 60/60 us respectively; link latency values 0.5 us, 0.5 us, and 0.2 us respectively; C500 FC2→FullMesh, C500 Tree→Tree, and 910B Mesh→FullMesh; AllGather parameter reuse from AllReduce.
- Protocol/startup policy: when the vendor selector exposes LL, LL128, or SIMPLE, the adapter uses that selected protocol to choose the small or simple startup. When C500 FC2 or HCCL leaves the protocol unobservable, the development-only fallback uses the versioned 64 KiB/4 MiB boundaries; LL and LL128 share the small-message startup. A selector result marked unresolved is rejected.
- Placeholder inputs requiring later source-backed update: `eta_ring=0.40`, tree/NVLS efficiencies, credit BDP values, 8 MiB bulk chunk, switch floor, FEC fields, retry-source fields, and `credits=64`. The FullMesh bandwidth itself is derived directly from the confirmed per-peer wire rate with no fitted efficiency. The A800/C500 spray chunk is 4096 bytes and the 910B spray chunk is 512 KiB as supplied for this development run. `wire_efficiency=1.0` and `phase=full` explicitly retain the upstream scale-up/full-collective behavior.
- Applicability: the adapter maps C500 FC2 and 910B Mesh to upstream FullMesh, maps C500 Tree to Tree, and checks every non-synthetic call against the versioned vendor selector before prediction. Current TP2 Serving defaults therefore select FC2 on aligned C500 payloads and Mesh on 910B; mismatched C500 alignment/size cases fail loud instead of silently running the wrong schedule. These registered profiles remain `development_only`, so their results are still unsupported for accuracy, publication, hardware comparison, or DSE claims until source-backed author profiles replace the remaining placeholder parameters. HD/NHR remains outside the observed selector domain.

## PCIe scope

The pinned upstream repository includes a C++/ns-3 PCIe fabric (`src/gpu-cluster/model/pcie-fabric.*`) and detailed RDMA/IBGDA integration described in `doc/PCIE.md`. It offers a bandwidth mode and an error-free TLP mode with Gen3/4/5 links, shared switch/root topology, credits, tags and read/completion transactions. The Python white-box surrogate loaded here has no PCIe API; updating this gitlink does not connect that C++ PCIe engine to Midlayer. Midlayer retains its existing independent PCIe transfer model.
